# تقرير حالات كيانات الأولوية في Asyncara

تاريخ التقرير: **2026-11-12**. حالة الإصدار: **EXPERIMENTAL**.

هذا تقرير عن الكيانات العشرة المطلوبة. المرجع المعتمد لحالة الكيان ككل هو
[docs/ROADMAP.md](../docs/ROADMAP.md#current-priority-status)، بينما يعرض
[تقرير القدرات](../docs/PRIORITY_CAPABILITIES.md) الأدلة الخاصة بالأجزاء المختبرة.

**تصحيح: الكيانات العشرة ما زالت `PARTIALLY_IMPLEMENTED` على مستوى الطلب الكامل.**
القول السابق إن تسعة كيانات اكتملت كان تصنيفًا غير دقيق: نقل حالة أجزاء محددة
منفذة ومختبرة إلى الكيان بأكمله، مع أن فجواته ما زالت مفتوحة. هذا الادعاء مسحوب.

توجد قدرات فرعية تستحق `IMPLEMENTED_AND_TESTED` في نطاقها المحدد، ونتائج اختباراتها
محفوظة أدناه. لكنها لا تكفي لإغلاق الكيان أو تقليص نطاق المطلوب دون بيان ذلك.
هذا تصحيح للتوثيق فقط؛ لا يضيف تنفيذًا أو اختبارات أو يحوّل إخفاقًا سابقًا إلى نجاح.

| Native Server | `PARTIALLY_IMPLEMENTED` | خادم CLI وHTTP/1.1، وتوجيه الطلبات، وTLS/mTLS، والبث المحدود والعمال |
| HTTP Client | `PARTIALLY_IMPLEMENTED` | curl multi، والطلبات المتزامنة، وHTTP/2 المخزّن، والبث عبر HTTP/1.1، والبروكسيات المحددة |
| Hyper HTTP Client | `PARTIALLY_IMPLEMENTED` | واجهة HttpClient على Hyper: الطلبات والأجسام والضغط والبث ضمن الحدود الموثقة |
| Broad HTTP Protocol/Proxy Certification | `PARTIALLY_IMPLEMENTED` | مصفوفة محلية لبروتوكولات وبروكسيات محددة؛ ليست شهادة توافق شاملة |
| PostgreSQL | `PARTIALLY_IMPLEMENTED` | libpq غير الحاجب، والمعاملات والنتائج المحدودة وTLS/mTLS في التكوين المختبَر |

## تقارير الكيانات

الوصف التالي للأجزاء المنفذة، وليس إقرارًا باكتمال الكيان. القيود والأعمال
المتبقية المذكورة لكل قسم ما زالت مفتوحة؛ حالة الأقسام العشرة جميعها جزئية.

### 1. Rust Hyper backend

المحرك الاختياري ينفذ نقل HTTP/1.1 عبر readiness وFFI، مع قبول محدود للعمليات،
وحل أسماء عبر العمال، والتحقق من TLS، وإدارة عمر الاتصالات ومسارات الفشل.
لا يعتمد انتظار الشبكة على استبدال المحرك بعمّال Tokio.

الأدلة: [مراجعة السلامة](../docs/HYPER_SAFETY_REVIEW.md)،
[TLS](../docs/HYPER_TLS.md)، واختبارات
[FFI](../tests/http/hyper_ffi.py) و[TLS](../tests/http/hyper_tls.py).
التحقق الحالي يتضمن مجموعة HTTP على الخلفيتين وبناء Rust/C مستقلًا من الأرشيف.
تبقى HTTP/2 وHTTP/3 والبروكسيات والتصديق على macOS/BSD خارج هذا النطاق.

### 2. Native Server

الخادم يوفر App وتوجيه الطلبات وmiddleware ومعالجات Fiber، وHTTP/1.1،
وTLS/mTLS، وبث الإدخال والإخراج بحدود، وتشغيل عدة عمليات عمال.
هو نمط التطوير الأساسي؛ توافق FPM الموجود لم يُحذف.

الأدلة: [تقرير الخادم](../docs/SERVER.md)، واختبارات
[البروتوكول](../tests/server/run.py)، [TLS](../tests/server/tls.py)،
[الإدخال](../tests/server/input.py)، [الإخراج](../tests/server/stream.py)،
و[العمال](../tests/server/workers.py). نجحت 14 حالة تشغيل على epoll/poll في
التحقق النهائي، ثم أُعيدت على البناء المستقل.

يبقى أيضًا reset غير مفسّر في اختبار GCC/poll/TLS للإدخال البطيء، كما هو موثق
في [أدلة بث طلبات الخادم](../docs/phase7/server-request-stream.json).
توجد اختبارات معالجات تجمع SQL وRedis وHTTP والملفات. يبقى فشل أولي
لانقطاع طلب PostgreSQL موثقًا دون تفسير مثبت. البث half-duplex، ولا يوجد
تصديق HTTP/2/3 للخادم أو دمج WebSocket upgrade. لا تثبت النتائج تفوقًا أدائيًا
مطلقًا أو تحملًا طويل المدة.

### 3. HTTP Client

العميل الأساسي يستخدم **تكامل curl multi المدفوع بالأحداث** للشبكة، وعمّال
الملفات عند الرفع والتنزيل. يشمل الطلبات المتزامنة وHTTPS الموثّق وHTTP/2
المخزّن، وبث HTTP/1.1 مع backpressure، وmultipart والتنزيل الذري.

أضيفت بيانات اعتماد Basic صريحة ومحدودة للبروكسي، مع فصل رؤوس الأصل عن
CONNECT، وملكية مستقلة للخيارات، وحماية مسارات الاستثناء المختبرة من كشفها.
الأدلة: [هندسة HTTP](../docs/HTTP_ENGINEERING.md)،
[مصادقة البروكسي](../docs/PROXY_AUTHENTICATION.md)،
[اختبار المصادقة](../tests/http/proxy_auth.py)، و[بوابة HTTP](../tests/http/run.py).
نجحت بوابة HTTP ذات 101 فحص. يبقى بث HTTP/2 مقيدًا لحماية حدود الذاكرة؛
HTTP/3 غير مصدّق.

### 4. Hyper HTTP Client

يوفر HttpClient على المحرك الاختياري طرق الطلب والرؤوس والأجسام، وgzip/deflate،
وبث الردود والرفع ضمن حدود موثقة. اختُبر أيضًا داخل Native Server مع قواعد
البيانات والملفات وRedis؛ لا يحتاج إلى اعتراض دوال cURL في PHP.

الأدلة: [الطلبات](../docs/HYPER_REQUESTS.md)،
[الضغط](../docs/HYPER_COMPRESSION.md)، [البث](../docs/HTTP_STREAMING.md)،
واختبارات [الطلبات](../tests/http/hyper_requests.py)،
[الضغط](../tests/http/hyper_compression.py)، و[البث](../tests/http/hyper_streaming.py).
لا توجد مطابقة كاملة لقدرات curl: redirects والبروكسيات وclient mTLS
وBrotli/zstd وHTTP/2/3 غير متاحة في هذا المحرك.

### 5. Broad HTTP Protocol/Proxy Certification

**الحالة باقية `PARTIALLY_IMPLEMENTED`.** الاختبارات المحلية المستقلة تغطي
HTTP/1.1 وHTTP/2 المخزّن، وHTTPS بشهادات CA خاصة، وHTTP/HTTPS forward proxy
وCONNECT، وثقة TLS مستقلة للبروكسي والأصل، ومصادقة Basic. اختُبر HTTP/2 داخل
نفق HTTPS CONNECT مصادَق عليه.

الأدلة: [HTTP/2](../docs/HTTP2_CLIENT.md)،
[HTTPS proxy](../docs/HTTPS_PROXY.md)،
[مصادقة البروكسي](../docs/PROXY_AUTHENTICATION.md)،
و[اختبار HTTP/2](../tests/http/http2.py).
نجحت مصفوفة المصادقة ذات 40 أمرًا عبر خمسة بناءات PHP والخلفيتين.
لا يثبت ذلك Digest/NTLM/Negotiate أو SOCKS أو HTTP/3 أو التوافق العام مع أجهزة
البروكسي والشبكات البعيدة والمنصات الأخرى. لم تُغيّر الحالة إلى مكتملة شكليًا.

### 6. PostgreSQL

يستخدم libpq غير الحاجب، مع binding ومعاملات callback تحافظ على connection
affinity، وحدود للنتائج والإشعارات، وذاكرة prepared statements محدودة،
وTLS/mTLS والتحقق من ملكية مسارات الشهادات.

الأدلة: [توافق قواعد البيانات](../docs/DATABASE_COMPATIBILITY.md)،
[prepared cache](../docs/POSTGRESQL_PREPARED.md)،
[mTLS](../docs/POSTGRESQL_MTLS.md)، [ملكية مسارات TLS](../docs/SQL_TLS_PATHS.md)،
واختبار [mTLS وNative Server](../tests/database/mtls_pg.py).
التكوين المختبَر هو PostgreSQL 16.15 / libpq 16.15. الاختبار داخل الخادم يشمل
المعاملات والإلغاء والانتظار المشترك والمهلة والتحقق المستقل من إغلاق الجلسات.

الإلغاء المحلي لا يضمن إقرارًا بإيقاف الاستعلام على الخادم. لا يوجد تصديق عام
لـWAN أو جميع الإصدارات أو تدوير الشهادات. بقيت ملاحظة libpq TLS عند التفريغ
العادي، وحجمها 109 بايتات، منفصلة ومحفوظة؛ كما بقي الانقطاع الأولي المذكور أعلاه.

### 7. MySQL / MariaDB

يستخدم التنفيذ state machine الخاصة بواجهات Connector/C start/continue،
مع statements مربوطة، ومعاملات callback وconnection pools وTLS/mTLS.
أُصلحت تهيئة ConnectionPool قبل App::listen دون بدء اتصالات مبكرًا؛ تبقى
المصانع وعمليات الاستعارة داخل Scheduler.

الأدلة: [التوافق](../docs/MYSQL_COMPATIBILITY.md)،
[mTLS](../docs/MYSQL_MTLS.md)، [مسارات TLS](../docs/SQL_TLS_PATHS.md)،
[اختبار MariaDB/Oracle](../tests/database/mtls_mysql.py)،
و[اختبار تهيئة Pool](../tests/pool_configuration.php).
النتائج مستقلة لـ**Oracle MySQL 8.4.13** و**MariaDB 11.8.9** باستخدام
Connector/C 3.4.10 وOpenSSL 3. يشمل النطاق التحقق الصارم من SAN لعنوان IP رقمي.
DNS/SNI TLS، ومصفوفات إصدارات ومصادقة أوسع، وواجهات prepared-cache إضافية
تبقى خارج التصديق الحالي.

### 8. Redis

يستخدم TCP/TLS غير الحاجب مع ACL وRESP2/RESP3، وحدود للردود وpipelines
والإشعارات، ومعاملات Redis وPub/Sub مخصص. تحفظ معالجة push هوية الإشعار
حتى لا يُحسب ردًا عاديًا لأمر آخر.

الأدلة: [ملكية الإشعارات](../docs/REDIS_NOTIFICATIONS.md)،
[مسارات الثقة](../docs/STREAM_TLS_PATHS.md)،
[اختبار push](../tests/database/redis_push.py)،
و[خدمات Native Server المشتركة](../tests/database/native_server.php).
التكوين المختبَر Redis 7.0.15. تحققت الاختبارات من إغلاق العملاء وإزالة مفاتيح
العمل بعد انتهاء الخادم. Cluster وSentinel وattributes وstreaming aggregates
وidle notification pump غير منفّذة ضمن هذا النطاق.

### 9. Native Filesystem

يوفر Files/File، وملكية مقابض الملفات، وعمليات جزئية وبثًا محدودًا، واستبدالًا
ذريًا مع خيارات sync، والتقاط أسماء الملفات عند قبول العملية. التنفيذ
**WORKER_BACKED_ASYNC** باستخدام أربعة عمّال pthread؛ ليس I/O قرصيًا غير حاجب
على مستوى النواة.

الأدلة: [الملفات](../docs/FILESYSTEM.md)،
[عقد دورة الحياة](../docs/IO_LIFECYCLE_CONTRACT.md)، واختبارات
[المسارات](../tests/filesystem_paths.php)،
[الاستبدال الذري](../tests/filesystem_atomic.php)،
و[ملكية النتائج](../tests/filesystem_buffer_ownership.php).
تغطي المجموعة الكاملة وبوابة Gate A هذه المسارات، ويستخدمها اختبار الخدمات
داخل Native Server. io_uring غير منفّذ، ولا توجد شهادة شاملة لتحمل انقطاع
الطاقة أو جميع أنظمة الملفات.

### 10. Memory Hardening

يشمل النطاق دفتر المحاسبة للتخصيصات التي تديرها Asyncara، وحدود العمليات
والنتائج والبث والإشعارات، وسياسات النسخ، وملكية الإلغاء وجمع النتائج والتنظيف.
تشمل الإصلاحات الجديدة حماية بيانات الاستثناءات وملكية خيارات البروكسي.

الأدلة: [حدود الموارد](../docs/RESOURCE_LIMITS.md)،
[تدقيق الملكية](../docs/NATIVE_OWNERSHIP_AUDIT.md)،
[نتائج التبعيات](../docs/DEPENDENCY_FINDINGS.md)،
و[سجل التحقق الحالي](../docs/phase7/proxy-services.json).
اجتازت اختبارات DEBUG Valgrind المحددة فحوص الأخطاء والفقد؛ نتائج GCC ASan/UBSan
محددة بالمسارات المشمولة ولا تعني أن Rust خضع لأدوات GCC نفسها.

تخصيصات PHP والمكتبات الخارجية والنواة والعمليات التابعة ليست كلها محسوبة
في الدفتر. نتائج distribution-PHP cyclic shutdown وlibpq TLS، وتقارير الفشل
الأصلية، لم تُحذف أو تُحوّل إلى PASS. لا تمثل هذه الحالة ضمانًا شاملًا لسلامة الذاكرة.

## نتائج التحقق المنفّذة

الأعداد التالية تخص مجموعات مختلفة، وبعضها يحتوي فحوصًا من مجموعات أخرى؛
لا تُجمع باعتبارها اختبارات مستقلة إضافية.

تغطي الخوادم الثلاثة في البناءات العادية وDEBUG، بينما فحوص GCC تغطي MariaDB
وOracle؛ استُبعد نجاح TLS الإيجابي لـlibpq من تلك المجموعة بسبب ملاحظة التفريغ
العادي المحفوظة، دون suppression. أول مصفوفة بروكسي سبقت إصلاح Pool فقط؛
مصفوفة الخدمات والبوابات النهائية تشمل الإصلاح.

النتائج مسجلة في [سجل المصدر والاختبارات والبصمات](../docs/phase7/proxy-services.json)
و[شهادة البناء المستقل](../docs/phase7/proxy-services-package.json).
تمت مراجعة بصمات تقاريرها عند إعداد هذا الملف؛ **لم تُعد الاختبارات أثناء مهمة
التوثيق هذه**. السجلات الخام المحلية ومساراتها وSHA-256 مسجلة في هذين الملفين.

## الإخفاقات والقيود التي بقيت محفوظة

- أول تشغيل PHP 8.3 لخدمات PostgreSQL داخل Native Server انقطع أثناء طلب
  باستعلام معلق. السبب غير محسوم؛ نجاح الإعادات لا يثبت تفسيره.
- أول تشغيل للخادم تحت Valgrind انتهى بـRemoteDisconnected ثم SIGTERM.
  لا يُعامل تقرير تخصيصات لحظة الإنهاء القسري كقياس تسرب بعد إغلاق طبيعي،
  ولا يُحوَّل ذلك التشغيل إلى PASS.
- الإعادات الكاملة تحت Valgrind استغرقت 9.492 و9.633 و9.851 ثانية داخل مهلة
  الخادم الأصلية البالغة 10 ثوانٍ. تأثير تكلفة الفحص تفسير محتمل، لكن لا يوجد
  عدّاد مهلة محفوظ من الفشل الأول لإثباته. الاختبار المقسّم دليل تشخيصي منفصل.
- بقيت حالات فشل إعداد الأدوات ومساعدات الاختبار موثقة، ومنها خطأ تمرير Request
  إلى وسيط نصي في إحدى أدوات التشخيص؛ صُحح المساعد دون تغيير مهلة الخادم.
- بقيت نتائج Phase 4 التاريخية: ساعة FPM ناجحة، وست ساعات فاشلة مع zero ticks،
  ومرحلة 24 ساعة لم تبدأ. الاختبارات الحديثة لا تعيد تصنيف تلك النتائج.
- لا توجد في هذا التقرير شهادة أداء تفوق جميع حلول PHP أو Go، ولا شهادة تحمل
  ست أو أربع وعشرين ساعة للمصدر الحالي، ولا ترقية للإصدار من EXPERIMENTAL.
